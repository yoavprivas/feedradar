# FeedRadar — אימות השלמת שלב א׳ לאחר תיקון האיסוף

נבדק בפועל ב־9.11.2026 על Windows, Node.js 24.22.1 ו־PostgreSQL 17.11. התוצאות מתייחסות למועד הבדיקה, ולא מבטיחות זמינות עתידית של אתרי צד שלישי.

## שורש התקלה והתיקון

ה־Frontend והתקשורת ל־API פעלו; הכשל היה בכיסוי מנגנון הגילוי. המנגנון הקודם חיפש בעיקר פידים מפורסמים וכתבות מובנות בתוך דף הבית. Ynet וכלכליסט מציגים בדף הבית קישורים לכתבות, אך המטא־נתונים הדרושים נמצאים בדפי הכתבות; ספורט 5 מפרסם News Sitemap דרך robots.txt. Google Finance מפנה את לקוח האיסוף ל־/finance/unsupported.

נוספו גילוי מפות חדשות, גילוי פידים באמצעות קישורים רגילים, וסריקה מוגבלת של קישורי כתבות באותו origin עם אימות JSON-LD/Open Graph בדף היעד. אין תנאים לפי hostname או רשימת חריגים לארבעת האתרים. robots, הגנות SSRF, הגבלת זמן וגודל נשארו בתוקף. נשמרים כותרת, קישור ותאריך בלבד.

רישום מקור ושמירת הכתבות הופרדו לעסקאות נפרדות ולסטטוסים נפרדים ב־API ובממשק. שגיאת שמירה אינה מוחקת אתר שנרשם. שגיאות למשתמש מוצגות בעברית.

## בדיקות אוטומטיות

- 24 בדיקות יחידה עברו, ללא כישלון או דילוג.
- 14 תרחישי אינטגרציה עברו מול PostgreSQL ושרת HTTP אמיתיים, בתוך בדיקת־אב (15/15 בדיווח runner). הרשת החיצונית מבוקרת בבדיקות אלה.
- TypeScript ו־production build עברו.
- רגרסיות חדשות: News Sitemap עם תאריך פרסום ולא lastmod; אימות מטא־נתונים בקישורי דף בית; סינון ניווט וקישורים חיצוניים; robots גם בדפי כתבות; כשל שמירה יזום אחרי רישום והתאוששות בסריקה הבאה.
- יתר הבדיקות מכסות פורמטים, תאריכים, מניעת כפילויות, פרסום חדש, מיון, כשל חלקי, תזמון, התמדה, הסרה ו־Origin/Host/SSRF.

## בדיקות חיות ונתונים

הזנת כתובות רגילות, ללא נתיבי פיד ידניים:

- Ynet: נוסף דרך הדפדפן, HTML, נשמרו בתחילה 12 כתבות עם תאריך פרסום.
- כלכליסט: POST דרך API של היישום החזיר 201, HTML, נשמרו בתחילה 12 כתבות עם תאריך.
- ספורט 5: POST החזיר 201, מפה מפורסמת ב־https://www.sport5.co.il/sitemap/articles/news-sitemap.xml, נשמרו 192 כתבות עם תאריך. המתאם מסווג כ־rss במסד משום שהוא מקור XML לסינדיקציה.
- Google Finance: נבדק דרך API ובדפדפן. התקבלה UNSUPPORTED_SITE והוצגה שגיאה בעברית. לא נרשם כמקור מצליח ולא נעשה ניסיון לעקוף את דף unsupported.

שאילתת PostgreSQL אימתה 3 מקורות ו־216 כתבות. הפיד הציג אותן, ורענון ידני פעל ללא שגיאות JavaScript. לאחר עצירה והפעלה מחדש של השרת וגם PostgreSQL אומתו כל 216 המזהים, המקורות והקישורים המקוריים. סריקת ההפעלה הבאה קלטה כתבה חדשה והפיד הציג 217. המקורות נשארו במעקב, בהתאם לבקשת המשתמש.

## pgAdmin

נרשם חיבור FeedRadar local לשרת הקיים 127.0.0.1:55432 ולמסד feedradar, ללא יצירת מסד חלופי. נוצר גיבוי של הגדרות pgAdmin לפני הרישום. נעשה שימוש במשתמש הקיים ובקובץ passfile תחת .local עם הרשאות Windows למשתמש המקומי בלבד. הסיסמה לא הוצגה ולא נוספה ל־Git.

נפתחו דרך pgAdmin גם public.articles (216 רשומות בזמן הבדיקה) וגם public.sources (3 רשומות), והנתונים נראו בפועל. הוראות פתיחה ב־README. קובץ הסיסמה מוגבל למסד feedradar; מסדי postgres ו־feedradar_test אינם יעד החיבור הזה.

## Git ומסירה

נבדקו כל 38 ה־blobs בשני ה־commits הקיימים, וכן הקבצים הנוכחיים, כנגד הסיסמאות המקומיות וסוגי מפתחות נפוצים. לא נמצאו התאמות. זו סריקה ממוקדת ולא הוכחה מתמטית להיעדר כל סוד אפשרי. .env.example מכיל placeholders; .env, .local, נתוני PostgreSQL, בינאריים, לוגים ותלויות מוחרגים. תיעוד, מקור, בדיקות וקובץ נעילת תלויות נשמרים במאגר; לא בוצע Push.

## מגבלות

אין תמיכה ב־Google Finance במנגנון הנוכחי. API ציבורי נתמך הוא WordPress המפורסם באתר, ולא כל API שרירותי. ב־HTML נבדקים עד 12 מועמדים בכל סריקה; אין הבטחה לאיסוף כל הכתבות או לארכיון מלא. מבני HTML וזמינות חיצונית עשויים להשתנות. אין התחברות, הפעלת JavaScript של המקור, עקיפת CAPTCHA, paywall או robots.

בדיקות התצוגה המקוריות ברוחבי 320/390/768/1024/1440 בוצעו במסירה הקודמת; בתיקון זה נבדקו מחדש תפעול ההוספה, השגיאה, סטטוס המקורות, הפיד והרענון. אין טענה לבדיקה במכשירים פיזיים. הפקודות לשחזור הבדיקות נמצאות ב־README.
