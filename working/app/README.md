# FeedRadar — שלב א׳

אפליקציה מקומית בעברית למעקב אחר כתבות מאתרים לבחירתך. פיד כרונולוגי ללא תמונות או תקצירים, הוספה והסרה של אתרים, איסוף ידני ואוטומטי ושמירה ב־PostgreSQL.

## הפעלה במחשב שבו הוקם הפרויקט

בתיקיית `projects/feedradar/working/app` מפעילים את `Start-FeedRadar.cmd` בלחיצה כפולה, או מריצים ב־PowerShell 7:

```powershell
./Start-FeedRadar.ps1
```

האפליקציה נפתחת ב־http://127.0.0.1:4310. הסקריפט מפעיל את PostgreSQL המקומי במקרה הצורך, ואז את השרת ברקע. לסיום הפעילות והסריקות מריצים `Stop-FeedRadar.cmd`, או `./Stop-FeedRadar.ps1 -StopDatabase`. סגירת לשונית הדפדפן בלבד אינה עוצרת את השרת. לוגים נמצאים ב־`.local/server.log` ו־`.local/server-error.log`.

ניהול אתרים: מזינים כתובת רגילה (למשל `https://www.nasa.gov`), לוחצים „הוספת אתר”, וחוזרים לפיד. הכתבות נפתחות באתר המקורי. הסרת אתר מוחקת את כתבותיו מהמסד ומהפיד; אפשר להוסיף את האתר מחדש, אך היסטוריה שכבר אינה במקור עלולה לא לחזור.

## התקנה נקייה במחשב אחר

נדרשים Node.js 22.12 ומעלה (מומלץ LTS), PostgreSQL 17 ומעלה, ו־npm או pnpm. סקריפטי הנוחות ל־Windows דורשים PowerShell 7; קוד האפליקציה אינו תלוי ב־Windows, ב־Codex או בהיסטוריית הצ׳אט.

1. בתוך תיקיית האפליקציה: `npm install` או `pnpm install --frozen-lockfile` (pnpm 11). קובץ `pnpm-lock.yaml` הוא נעילת הגרסאות שנבדקו; התקנה עם npm עשויה לבחור גרסאות שונות בטווחים המוגדרים.
2. צרו ב־PostgreSQL משתמש ייעודי ושני מסדי נתונים. דרך `psql` כמשתמש מנהל:

```sql
CREATE ROLE feedradar LOGIN PASSWORD 'replace-with-a-long-local-password';
CREATE DATABASE feedradar OWNER feedradar;
CREATE DATABASE feedradar_test OWNER feedradar;
```

3. העתיקו `.env.example` אל `.env`, והגדירו `DATABASE_URL` ו־`TEST_DATABASE_URL` בהתאם לשרת, לפורט ולסיסמה. הפורט המקובל בהתקנה רגילה הוא 5432; הפורט בהתקנה המקומית שבפרויקט הוא 55432. תווי סיסמה מיוחדים ב־URL דורשים percent-encoding.
4. הריצו:

```text
npm run db:migrate
npm run build
npm start
```

פתחו http://127.0.0.1:4310. הטבלאות נוצרות גם באופן אוטומטי בהפעלת השרת. לעצירה כשהשרת רץ בחלון המסוף: Ctrl+C.

ב־Windows אפשר להשתמש בבינאריים הרשמיים ללא התקנת שירות מערכת: הורידו ZIP של PostgreSQL מהקישור ב־https://www.postgresql.org/download/windows/, חלצו, והריצו `./scripts/local-db.ps1 start -PgBin 'C:/path/to/pgsql/bin'`. הסקריפט ייצור אשכול מקומי, סיסמאות אקראיות, מסדים ו־`.env` רק אם אין כבר `.env`. הוא שומר את הנתונים ב־`.local/postgres`, ומאזין ל־127.0.0.1 בלבד. בהפעלות חוזרות עם מיקום בינאריים מותאם יש להפעיל את סקריפט המסד עם אותו `-PgBin` לפני הפעלת השרת ב־`npm start`.

## הגדרות

- `PORT`: ברירת מחדל 4310; השרת נגיש מהמחשב המקומי בלבד.
- `SCAN_INTERVAL_MINUTES`: ברירת מחדל 30, טווח 5–1440. שינוי דורש הפעלה מחדש.
- `REQUEST_TIMEOUT_MS`: ברירת מחדל 12000, טווח 1000–30000.
- `MIN_REFRESH_SECONDS`: ברירת מחדל 60, טווח 10–3600; מונע רענונים תכופים מדי.

עם הפעלת השרת מתבצעת סריקה ראשונה ולאחריה סריקות במרווח המוגדר, הנמדד מסיום הסריקה. בזמן סריקה אין סריקה מקבילה. הדפדפן בודק את מצב הפיד כל 15 שניות כאשר הלשונית גלויה. אין תזמון כששרת האפליקציה כבוי.

## תמיכה באתרים וגבולותיה

סדר הגילוי: כתובת פיד ישירה; קישורי RSS/Atom/JSON Feed המפורסמים ב־HTML; מפות חדשות (News Sitemap) המפורסמות ב־robots.txt; נתיבים נפוצים `/feed/`, `/rss.xml`, `/feed.xml`; WordPress REST API המפורסם באמצעות `rel=https://api.w.org/`; ולבסוף HTML עם JSON-LD של Article/NewsArticle/BlogPosting או רכיבי `article` סמנטיים. כאשר אין רשימה מובנית, נבדקים עד 12 קישורי כתבות באותו origin; כתבה מתקבלת רק אם דף היעד מאשר אותה באמצעות JSON-LD או Open Graph מסוג article. קישורי ניווט אינם נאספים. חלון תחילת בקשות הכתבות הוא 45 שניות, וכל בקשה עדיין כפופה למגבלת הזמן ול־robots. אפשר להזין גם URL של מדור כדי לעקוב אחרי פיד ייעודי שמפורסם בו. אם אין דרך נתמכת, האתר אינו נשמר.

אין תמיכה אוניברסלית בכל API או אתר. אין הפעלת JavaScript של אתר, התחברות, עקיפת CAPTCHA, paywall או חסימות. מבנה אתר עשוי להשתנות. המערכת מכבדת robots.txt, לרבות ביעד של הפניה, ו־Crawl-delay עד 30 שניות; עיכוב גדול מכך אינו נתמך. תקלה בשליפת robots חוסמת איסוף באותו ניסיון. נתיבים ציבוריים מותרים לפי robots אינם כשלעצמם רישיון משפטי — השתמשו במקורות המתירים שימוש כזה לפי תנאיהם.

מגבלות מכוונות: עד 50 אתרים, עד 200 פריטים בכל פיד/סריקה, עד 2MB לתגובה, עד 5 הפניות, עד 6 ניסיונות פיד לכל אתר. אלה מגבלות עבודה מקומית ואינן הבטחה לארכיון מלא או לקליטת כל כתבה אם המקור מפרסם יותר פריטים מהפיד בין סריקות. פריטים שנשמרו נשארים בין סריקות. אין שמירת גוף כתבה או תמונות; דפי HTML עשויים להיקרא כדי לחלץ כותרת, קישור ותאריך בלבד.

תאריך פרסום נשמר רק משדה פרסום מקורי עם שעה ואזור זמן. זמן עדכון או איסוף אינו מחליף אותו. תאריך לא תקין, חסר, יום בלבד או שעה ללא אזור זמן מוצגים כלא זמינים וממוינים בסוף. URL מנוקה מ־fragment ומפרמטרי מעקב נפוצים. הייחודיות היא לפי אתר + URL; כתבות מאתרים שונים יכולות להפנות לאותו קישור ולהופיע בנפרד.

## פיתוח וארכיטקטורה

- `src/`: React, TypeScript, עיצוב RTL ו־SVG מקומיים; אין גופנים או CDN חיצוניים.
- `server/network.ts`: בדיקת URL ו־IP, חסימת רשתות פנימיות, הצמדת DNS לכתובת מאומתת, robots, מגבלות זמן וגודל.
- `server/collector.ts`: גילוי ומתאמי RSS, Atom, JSON Feed, WordPress ו־HTML.
- `server/db.ts`: סכמת sources/articles, שאילתות פרמטריות ועסקאות PostgreSQL.
- `server/scanner.ts`: תזמון, מניעת סריקות חופפות ובידוד כשל מקורות.
- `server/app.ts`: API, הגנות Host/Origin וכותרת ייעודית לפעולות כתיבה.
- `server/index.ts`: חיבור הרכיבים והגשת build של הממשק באותו origin.

לפיתוח מהיר אפשר להפעיל `npm run dev` ובמסוף נוסף `npm run dev:ui`. שרת Vite מפנה את `/api` ל־4310. בגרסת המסירה משתמשים ב־`npm run build` ואז `npm start`.

## בדיקות

```text
npm test
npm run test:integration
npm run build
```

בדיקות היחידה משתמשות במקורות מדומים ומכסות פורמטים, תאריכים, robots וכתובות מסוכנות. בדיקות האינטגרציה משתמשות בשרת HTTP וב־PostgreSQL אמיתי, ובודקות הוספה/מחיקה, מיון, כפילויות, פריט חדש, כשל חלקי, תזמון, התמדה והגנת בקשות. הן דורשות `TEST_DATABASE_URL` ויוצרות ומוחקות רק schema אקראי עם קידומת `test_`; אינן משתמשות ב־`DATABASE_URL`.

בדיקת רשת אופציונלית: `node --import tsx scripts/smoke-live.ts`. היא בודקת Ynet, כלכליסט, ספורט 5 ו־Google Finance בלי להוסיף אותם למעקב. תוצאות עשויות להשתנות לפי האתר או הרשת. דוח האימות של המסירה נמצא ב־`VERIFICATION.md`.

## סודות ו־Git

`.env`, תיקיית `.local`, בינאריים של PostgreSQL, לוגים, node_modules ו־dist מוחרגים. אין לשתף `.env`, את סיסמת מנהל המסד המקומית או את תיקיית הנתונים. `.env.example` מכיל placeholders בלבד. הקוד מוכן ל־GitHub, אך אין לבצע push ללא אישור המשתמש.

אין בשלב א׳ פריסה לענן, Docker, משתמשים והרשאות, התראות או תשתיות scale. לפני שינויי schema בעתיד יש להוסיף migrations ממוספרים ולגבות נתונים; סכמת שלב א׳ היא יצירה חוזרת בטוחה של המבנה הראשוני.

## סטטוס הוספה לעומת איסוף

רישום מקור ושמירת כתבות הם עסקאות נפרדות. כשל בשמירה אחרי הרישום אינו מסיר את האתר: מוצגת אזהרה ונעשה ניסיון בסריקה הבאה. ה־API מחזיר registrationStatus ו־collectionStatus, וברשימת האתרים מוצג סטטוס האיסוף בנפרד מהיות האתר במעקב. אם מלכתחילה אין דרך איסוף נתמכת, האתר אינו נרשם.

## צפייה ב־pgAdmin במחשב זה

1. הפעילו FeedRadar כדי להפעיל גם את PostgreSQL.
2. פתחו pgAdmin 4 ובחרו Servers → FeedRadar local → Databases → feedradar → Schemas → public → Tables.
3. לחצו לחיצה ימנית על sources (אתרים) או articles (כתבות), ואז View/Edit Data → First 100 Rows.

החיבור משתמש בשרת הקיים 127.0.0.1:55432, במסד feedradar ובמשתמש feedradar. הסיסמה אינה בתיעוד: היא נקראת מקובץ .local/pgadmin.pgpass עם הרשאות Windows למשתמש המקומי בלבד. אין להעלות או להעביר קובץ זה. ההגדרה מקומית ואינה נכללת בחבילת המקור; במחשב אחר יש להגדיר חיבור למסד המותקן שם.

בבדיקה חיה ב־9.11.2026 נוספו Ynet, כלכליסט וספורט 5. Google Finance הפנה את הלקוח לדף unsupported ולא סיפק מקור חדשות נתמך; לא בוצע ניסיון לעקוף את המגבלה. אין התחייבות שכל כתבה מכל אתר תיאסף.
